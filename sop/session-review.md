# SOP: session-review（会话复盘）

输入：本次产物、工具错误、用户纠正
输出：反馈记录、候选改进项
检查点：不擅自修改长期规则

## 步骤

1. 对照本次 run 账本（runs/runs.jsonl 最新记录）核对：产物哈希与实际文件一致。
2. 记录五项：是否完成、哪里需人工纠正、用时、关键来源是否可回溯、下次只改什么。
3. 用户明确纠正过的点：
   - 属于本次任务口径 → 写入 feedback/round-N.md 草稿；
   - 属于长期偏好/规则 → 只 `pgm-ctl propose --type preference ...` 提交候选，
     由用户在 PGM 管理入口确认。Agent 无权把纠正直接写成生效规则。
4. 候选改进写入 feedback/proposals.md；流程模板改进待用户确认后改 SOP。
5. 不删除、不改写历史记录；错误照实留档（error 字段）。
