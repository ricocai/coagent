# ADR-0003: 事件到候选记忆的提炼管线（本地模型、无工具、候选边界）

- 状态：已采纳（2026-09-26）
- 关联：ADR-0001（适配器架构）、ADR-0002（会话采集）、设计 v0.4 §5.2 / §11.7 / §12.5

## 背景

ADR-0002 打通了 dsh 原生会话 → PGM 事件的自动采集，但采集回流的是**原始对话事件**。
若候选记忆仍靠人工 `propose`，随会话量线性增长会积压确认收件箱——记忆库的价值上限
由数据质量与提炼吞吐共同决定。设计 §11.7 为「私人历史候选抽取」预留了明确路由。

## 决策

1. **抽取走本地模型**（默认 MTPLX `127.0.0.1:8001` / `mtplx-flash-next-optimized-speed`，
   LM Studio 为已验证备用）：模型端点非回环地址时 CLI 默认拒绝启动（`--allow-remote`
   显式越过且打印警告），实现「不自动云端回退」（§11.7）。
2. **提炼器无执行能力**：抽取调用是纯 chat completion，请求体不带 `tools`/`tool_choice`
   字段；单元测试锁定该性质。
3. **只信真人输入**：仅对 `role=user` 的 committed 事件提炼。助手消息是建议不是决定
   （§12.5 角色测试），不得成为候选的证据来源。
4. **只产生候选**：经 `POST /v1/proposals` 提交并附 `evidence_ids`（来源事件 id，客户端
   生成、可经 `/v1/evidence` 回溯）。绝不调用 decide 接口——审批权只在用户（§5.2）。
5. **敏感度继承 + 二次脱敏**：候选 classification 取来源事件的最高敏感级（local_only
   优先）；模型输出内容提交前再过一次 `redact`（模型可能复述原文中的密钥）。
6. **宁缺毋滥**：模型输出空数组是合法结果，直接 ledger committed，不重跑；输出经严格
   schema 校验（类型枚举、长度上限、evidence 索引合法），非法项静默丢弃。
7. **两阶段 ledger 幂等**：propose 前写 pending、成功后写 committed（JSONL 追加，
   崩溃安全）。pending 批次默认跳过（宁可漏提不重提——重复候选污染确认收件箱），
   确认失败后用 `--retry-pending` 恢复。
8. **数据源为本机 outbox**：不新增 PGM 读接口（PGM 无事件列表端点）；outbox 记录里
   已含完整事件与 event_id，提炼与采集通过 ledger 解耦（各自幂等、互不阻塞）。

## 后果

- 正向：候选生成自动化，且每条候选可回溯到原始事件（evidence_ids）；敏感数据不出本机。
- 代价：引入对本地模型端点的运行时依赖——模型不在线时提炼暂停（批次留在 pending），
  但不影响采集与上下文读取。
- 局限：POC 阶段提炼质量依赖单次 prompt（无二次校验/自一致性）；候选粒度偏粗。
  后续若误报率高，优先加「抽取后自检」第二遍模型调用，而不是放宽校验。

## 验证

- 单测 20 项（回环守卫、无 tools、schema 校验、脱敏、敏感度继承、两阶段幂等、
  失败恢复、空输出容错），全套 50/50 通过。
- 真实数据：10 条 committed 用户事件 → 1 批 → MTPLX 真实调用 → 0 候选（内容确无
  长期价值，宁缺毋滥生效），批次 committed 不重跑。
