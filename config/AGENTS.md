# 个人 Agent 全局工作规则（co-agent / PGM 记忆）

## 任务前置（每个非平凡任务的第 1 步，先于检索网页或读本地文件）

1. 调用 `mcp__pgm__memory.build_context`，参数：`purpose` 一句话任务用途，
   `query` 可选关键词。返回 `snapshot_id` 与记忆正文。
   - 失败或超时：如实告知「记忆层不可用」；依赖历史决定/偏好的任务在此阻塞，
     不得用本地旧文件或猜测冒充当前有效记忆。
2. 在最终答复末尾的「运行记录」小节报告 `snapshot_id` 与本任务用途。
3. 使用上下文时严格三分：**用户已确认决定 / 助手建议（未确认）/ 未决问题**；
   每条重要结论附 `[M:mem_id@v]`（记忆）或 `[E:ev_id]`（事件证据）引用。
   查不到就写「未验证」，不得推测冒充。

## 任务中

4. 需要某条结论的原始出处 → `mcp__pgm__memory.get_evidence`（按 event_id 读回）。
5. 快照可能过期（有效记忆随时可能被修订）：**执行副作用工具（写文件、发请求、交易）之前
   重新 `build_context` 取新快照**，不要复用旧 snapshot 的内容做关键决策。

## 任务收尾

6. 本任务产生了新的长期事实/决定/偏好/待办 → 只走 `mcp__pgm__memory.propose`
   提交候选（附 evidence_ids）；**绝不自行确认**，确认权在用户（PGM 收件箱）。
7. 调用 `mcp__pgm__memory.events_flush` 回流本轮事件（幂等，失败不阻塞答复）。

## 边界

- 不得宣称「用户已确认 X」，除非上下文中该记忆 status=active 且有引用。
- 工具失败必须如实报告；不静默降级、不假装调用成功。
- 技能目录（context-pack / research-brief / session-review）与本规则冲突时，
  以本规则的候选/确认边界为准。
